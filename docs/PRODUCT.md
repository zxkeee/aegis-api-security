# AEGIS — продуктовый one-pager

> Источник правды для позиционирования. README, лендинг и демо-сценарий
> наследуют формулировки отсюда. Держим честным: границы продукта здесь же,
> чтобы демо не переобещало.

## Тезис (одно предложение)

**AEGIS — self-hosted шлюз защиты API: один Go-бинарник, который встаёт
reverse-proxy'ем перед твоими API, строит живую карту «кто → куда → с какими
данными ходит», оценивает их защищённость и блокирует API-специфичные атаки
(BOLA / BFLA / enumeration), которые сигнатурный WAF не видит — при этом ни байта
трафика не уходит в чужое облако.**

## Проблема, которую решаем

API стали основной поверхностью атаки, но классический WAF защищает её плохо:
он знает сигнатуры (SQLi, XSS), но не знает **бизнес-контекст** — кому какой
объект принадлежит, какой потребитель что обычно делает, где утекает PII. Атаки
уровня OWASP API Top-10 (BOLA, BFLA, перебор объектов) для сигнатурного WAF
выглядят как валидные запросы. Плюс команды часто **не знают свой реальный
API-периметр**: shadow-эндпоинты, недокументированные методы, забытые версии.

## Идея продукта: See → Protect → Prove

1. **See** — нельзя защитить то, чего не видишь.
   Пассивный discovery, нормализация путей, shadow/zombie/undocumented
   эндпоинты, классификация PII/PCI в трафике, posture-score 0–100,
   OpenAPI-drift.
2. **Protect** — inline-защита в одном процессе.
   WAF (Coraza), JWT-auth, rate-limiting, IP/bot/threat-контроли,
   **BOLA/BFLA enforcement на проверенных JWT-ролях**, DLP-маскирование ответов.
3. **Prove** — язык покупателя и комплаенса.
   Posture-scoring, persistent audit log, multi-tenancy, отчёты JSON/CSV,
   Prometheus-метрики.

## Ров (в чём мы реально сильны)

- **Self-hosted, единый бинарник, без агентов, data residency by-default.**
  Конкуренты уровня Imperva / Salt / Noname — дорогой SaaS, которому нужно
  зеркалировать трафик или пускать его в своё облако. Целый сегмент (финтех,
  медицина, гос, regulated mid-market) этого не может или не хочет.
- **Inline + passive в одном процессе.** Конкуренты обычно или-или.
- **Behavioral detection поверх API-контекста** (consumer-граф), а не сигнатуры.
  Сигнатурный WAF знает «похоже на SQLi». AEGIS знает «этот потребитель обычно
  трогает 3 объекта, а сейчас перебрал 300».

## Кому продаём (ICP)

Платформенные и API-команды в regulated mid-market (финтех, health, gov),
работающие on-prem / в собственном VPC, которым нужна data residency и которые
живут на Kubernetes. Те, **кого Imperva не возьмёт в клиенты или кто не пустит
SaaS в свой контур.**

## Против кого и как формулируем

НЕ «дешёвый Imperva». Позиционирование: **«API-security для self-hosted —
discovery + защита от API-abuse + posture, в твоём контуре, без SaaS».**
Паритет показываем там, где сильны (discovery, BOLA/BFLA, posture), широту
добираем со временем.

## Осознанные границы (что НЕ обещаем сегодня)

Демо не должно подразумевать паритет по всей сюите. Сейчас слабее/нет:

- WAF: ~12 самописных правил, не полный OWASP CRS.
- OWASP API Top-10: покрыто ~4/10 (API1/API5 enforcement, API3/API9 findings).
- Нет ML-классификации ботов, нет L7-DDoS, нет client-side (Magecart) защиты.
- Нет Account Takeover / credential-stuffing детекта (в роадмапе, A3).
- Классификатор данных: 4 типа (card/ssn/email/phone), без PHI/secrets/context.

Полный статус «готово / частично / нет» — в `ROADMAP.md` и
`RELEASE-CHECKLIST.md` (источник правды по реализации).

## Демо-нарратив (одно прохождение)

1. Поднять gateway перед тестовым API → за минуты в каталоге появляются
   эндпоинты с нормализованными путями.
2. Показать posture: какой эндпоинт unprotected, какой светит PII без auth
   (finding API3), какой shadow (API9).
3. Запустить перебор object-ID → AEGIS ловит BOLA и пишет объяснимый `why`.
4. Показать audit log + posture-score + отчёт — «вот доказательство для аудита».

## Следующий функциональный шаг (усиливает «Protect»)

**Schema enforcement (positive security):** активная валидация запросов против
импортированной OpenAPI-схемы (тип / required / enum / формат), а не только
drift-репорт. Закрывает разом часть API6 (mass assignment) + API8 и инъекции,
переиспользует готовый парсер спеки и превращает discovery из наблюдателя в
защиту — прямой паритет с killer-фичей Imperva. См. `ROADMAP.md` (B2).
